# وِثاق | WATHAQ

منصة برامج ولاء للمتاجر والمطاعم والمقاهي، تنطلق من عدن، اليمن. العميل مجاني، والتاجر يشترك شهريًا.
الحالة: **المرحلة الأولى قيد التنفيذ** (الأساس التقني). لا يوجد تطبيق واجهات بعد.

## البنية
| المسار | المحتوى |
|---|---|
| `supabase/migrations` | هجرات قاعدة البيانات بالترتيب (مطبّقة على `wathaq-dev`) |
| `supabase/tests` | اختبارات الأمان والصلاحيات (SQL) |
| `packages/design-tokens` | مصدر الألوان والخطوط والمسافات، ويولّد CSS وTypeScript |
| `i18n/ar.json` | نصوص الواجهة العربية (الإنجليزية لاحقًا دون تعديل الكود) |
| `assets/brand` | صور الشعار المرجعية (PNG، ليست نسخًا للإنتاج) |
| `docs` | التوثيق |

## التشغيل من البداية
1. أنشئ مشروع Supabase للتطوير فقط، وانسخ `.env.example` إلى `.env.local` واملأه.
2. طبّق الهجرات بالترتيب: `supabase db push` (أو من محرر SQL بالترتيب نفسه).
3. شغّل `supabase/tests/rls_security_tests.sql`. النتيجة تظهر في نص الخطأ المقصود، ويجب أن تكون كل الأسطر PASS. لا تُجرِه على بيانات حقيقية.
4. ولّد الـ tokens: `node packages/design-tokens/build.mjs` (يفشل إن لم يتحقق التباين المطلوب).

## قواعد لا تُكسر
- لا يكتب العميل أو التاجر في الأرصدة أو العمليات. الخادم مصدر الحقيقة.
- لا مفاتيح سرية في المستودع. `service_role` للخادم فقط.
- لا بيانات وهمية في الإنتاج، وبيانات الاختبار معلّمة بـ `is_test`.

## تطبيق العميل (النسخة 0.1)
- المصدر: `app/src/` · الناتج الجاهز للنشر: `public/` (يُولَّد بـ `node app/build.mjs`) · الملف الرئيسي: `public/index.html`.
- اختبار سريع: `node app/test/smoke.mjs` · النشر والاختبار على الهاتف: `docs/TESTING_V0.1.md`.
- سير العمل: `.github/workflows/ci-deploy.yml`.

# اختبار النسخة 0.1 (تطبيق العميل)

## 1) إعداد Supabase (مرة واحدة، من لوحة المشروع wathaq-dev)
1. **Authentication → Sign In / Providers → Phone:** فعّل المزوّد، واختر مزوّد الرسائل (Twilio). للاختبار بأرقام تجريبية تكفي قيم مؤقتة للمفاتيح، لأن Supabase لا يستخدم بيانات المزوّد مع الأرقام التجريبية لكنه يشترط تهيئته.
2. في **Test Phone Numbers and OTPs** أضف: `967777000001=123456` (بلا علامة +)، وحدد **Test OTPs Valid Until** بتاريخ قريب. احذف الأرقام التجريبية قبل أي إطلاق.
3. **Authentication → URL Configuration:** ضع رابط موقع GitHub Pages في Site URL وفي Redirect URLs (يلزم لجوجل فقط، فالبريد والهاتف برمز لا برابط).
4. (اختياري) **الدخول بالبريد برمز من 6 أرقام:** فعّل Email في Providers، وتأكد أن **Email OTP Length = 6**. ثم من **Authentication → Email Templates** عدّل قالبي **Magic Link** و**Confirm signup** بحيث يعرضان الرمز لا الرابط:
   - العنوان: `رمز الدخول إلى وِثاق`
   - المحتوى: `<div dir="rtl"><h2>رمز التحقق</h2><p>رمزك للدخول إلى وِثاق:</p><p style="font-size:28px;font-weight:bold;letter-spacing:6px">{{ .Token }}</p><p>صالح لمدة قصيرة. لا تشاركه مع أي شخص.</p></div>`
   - احذف أي `{{ .ConfirmationURL }}` من القالبين، وإلا يصل الرابط مع الرمز.
   - الإرسال الافتراضي للبريد محدود بعدد قليل من الرسائل في الساعة؛ للاستخدام الفعلي أعدّ SMTP خاصًا.
   - جوجل يحتاج إعدادًا منفصلًا ويظهر في التطبيق فقط إن فُعّل.
واتساب مؤجل: الدخول عبر الرسالة النصية فقط.

## 2) GitHub
1. ارفع محتويات المستودع كاملًا (وليس ملفين فقط) إلى فرع `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. سيعمل `.github/workflows/ci-deploy.yml`: فحص الألوان، فحص الصياغة، اختبارات الدخان، بناء `public/`، فحص عدم وجود مفاتيح سرية، ثم النشر. الرابط يظهر في تبويب Actions.

## 3) سيناريو الاختبار على الهاتف
1. افتح الرابط ← تسجيل الدخول ← الرقم `777000001` ← رمز `123456`.
2. اكتشف: ثلاثة متاجر تجريبية (معلّمة «بيانات تجريبية») ← افتح متجرًا ← اقرأ الشروط ← انضم.
3. تفتح بطاقتك بتقدم صفر. زر الاستبدال معطّل بصدق: الاكتساب والاستبدال لم يُنفَّذا بعد (دوال الخادم).
4. جرّب: قطع الإنترنت (يظهر الشريط ويبقى آخر ما حُمّل)، والمظهر الداكن، وتغيير الاسم، والمفضلة، وتسجيل الخروج.

## 4) ما لم يُختبر بعد
تدفق Supabase الحقيقي (الدخول والجلب) لم يُشغَّل من بيئتي لعدم وجود اتصال بالإنترنت؛ الذي اختُبر منطق التطبيق بواجهة مزيفة. أي خطأ يظهر عندك يُرسل لي بنصه أو بلقطة شاشة.


# اختبار النسخة 0.4: الاكتساب والاستبدال من البداية للنهاية
الصفحات بعد النشر: العميل `/` · الموظف `/staff/` · التاجر `/merchant/`. تسجيل الدخول مشترك بينها (جلسة واحدة لنفس المتصفح).
1. حسابان: حسابك الأول (مالك) وحساب ثانٍ (موظف). سجّل دخول كل منهما مرة واحدة في تطبيق العميل أولًا.
2. من محرر SQL شغّل `supabase/seed/dev_roles.sql` بعد استبدال البريدين: يصبح حسابك مالكًا للمتاجر التجريبية، والثاني موظفًا بصلاحيتي الإصدار والتأكيد.
3. **الاكتساب:** العميل (هاتف موثّق بالرسالة النصية) ينضم لبرنامج «مقهى النموذج». الموظف يفتح `/staff/` ← «عملية مؤهلة» ← إصدار رمز. العميل: الرئيسية ← «لدي رمز اكتساب» ← يدخل الرمز خلال دقيقتين ← يُضاف ختم.
4. **الاستبدال:** بعد اكتمال الأختام (الهدف 8) يضغط العميل «استبدال: قهوة مجانية» فيظهر رمز بعدّاد. الموظف: «استبدال مكافأة» ← يدخل الرمز ← يُخصم الرصيد، ويظهر للعميل «تم الاستبدال بنجاح» تلقائيًا خلال نحو 8 ثوانٍ.
5. جرّب الأخطاء: إعادة إدخال الرمز نفسه، رمز بعد انتهاء وقته، حساب هاتفه غير موثّق (دخل بالبريد فقط).
ملاحظة: التسجيل بالبريد فقط لا يوثّق الهاتف، فلا يستطيع صاحبه جمع الأختام. هذا مقصود وفق قرارك؛ مسار «ربط رقم الهاتف» لم يُبنَ بعد.

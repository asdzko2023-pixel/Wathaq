# حالة تنفيذ واجهات WATHAQ-CORE

آخر تحقق: 2026-11-19  
الفرع: `build/wathaq-premium-foundation`

## البنية الحالية
- تطبيق ويب تقدمي PWA بواجهة عربية RTL، مبني بـ HTML/CSS/JavaScript ES modules.
- واجهة العميل الرئيسية أعيد تصميمها بهوية البنفسجي الملكي والذهبي، وبطاقات الرصيد والبرامج والأنشطة والتنقل السفلي المتجاوب؛ الأرصدة والحركات تعرض من قاعدة WATHAQ-CORE فقط.
- المصدر: `web/`، والحزمة القابلة للاستضافة: `public/`، والبناء عبر `node app/build.mjs`.
- قاعدة البيانات: مشروع Supabase مستقل `WATHAQ-CORE`، وليس مشروع NOVEXA أو قاعدة WATHAQ القديمة.
- هذا الإصدار ليس APK أصليًا بعد؛ يمكن تثبيته كتطبيق PWA على Android بعد الاستضافة عبر HTTPS.

## ما نُفّذ في الواجهة

| المجال | التنفيذ الحالي |
|---|---|
| الهوية | WATHAQ Royal Purple + Gold، خط عربي، RTL، شعار SVG، بطاقات زجاجية/ناعمة، حالات تحميل وتنبيه |
| العميل | لوحة رئيسية متجاوبة مستوحاة من المرجع المرئي، تسجيل هاتف OTP، اكتشاف البرامج النشطة، البحث، المفضلة، الانضمام، أرصدة وحركات ومكافآت حقيقية، تنقل سفلي |
| QR العميل | إصدار رمز اكتساب أو استبدال مؤقت، وعرض QR قابل للمسح |
| التاجر | إنشاء ملف متجر بانتظار المراجعة، رفع الشعار، إنشاء برنامج نقاط/أختام، إدارة المكافآت والصور، نشر/إيقاف البرنامج |
| الموظف | قبول دعوة هاتفية، صلاحيات محددة، تأكيد اكتساب النقاط/الأختام والاستبدال |
| ماسح QR | قراءة QR بالكاميرا الخلفية عبر BarcodeDetector عند دعم المتصفح؛ إدخال الرمز يدويًا كبديل |
| Super Admin | عرض طلبات المتاجر المعلقة واعتمادها أو رفضها |
| التحليلات | مخطط نشاط التاجر لآخر سبعة أيام |
| PWA | manifest وأيقونة وservice worker لتخزين ملفات الواجهة الثابتة |

## ما تم التحقق منه
- فحص JavaScript syntax في GitHub Actions.
- توليد `public/` ومقارنته بالمصدر.
- فحص وجود ملفات الحزمة وملف bootstrap والاختبارات.
- رفع artifact باسم `wathaq-core-public`.
- اختبارات قاعدة البيانات الحية موثقة في `docs/SECURITY_REVIEW.md`.

## ما لم يكتمل بعد
- مزود SMS وإثبات وصول OTP إلى أرقام حقيقية في اليمن.
- اختبار كامل على هاتف Android حقيقي مع حسابات عميل/مالك/موظف منفصلة.
- إنشاء أول Super Admin.
- APK أصلي/Capacitor؛ الموجود حاليًا PWA فقط.
- الاشتراكات والفوترة، الإشعارات، الدعم والبلاغات، تقارير متقدمة، إعدادات الحساب وحذفه، وساعات عمل ومواقع المتاجر.
- اختبار قابلية الاستخدام وإمكانية الوصول على أجهزة فعلية، واختبار حمل واختراق مستقل.

## قيود تشغيلية
- عند عدم توفر الإنترنت، قد تُفتح ملفات الواجهة المخزنة، لكن معاملات الولاء والمصادقة تحتاج اتصالًا بالخادم.
- مسح QR يحتاج HTTPS وإذن كاميرا ومتصفحًا يدعم `BarcodeDetector`. أدخل الرمز يدويًا إذا لم يتوفر الدعم.
- لا تضع مفتاح service-role أو أي سر في `web/config.js`; المفتاح الموجود publishable فقط.
- لا تعتبر نجاح CI وحده دليلاً على جاهزية الإنتاج.
